# 채팅 운영 안내 (신고 확인 · 채팅 금지 · 계정 정지)

App Store 심사 지침 1.2(사용자 제작 콘텐츠)와 Google Play UGC 정책이 요구하는 것 — 걸러내기, 신고, 차단, **신고에 대한 운영자의 조치** — 가운데 마지막을 맡는 문서다.
약관과 개인정보 처리방침에 적힌 "위반 시 채팅 제한·계정 정지"를 실제로 하는 방법이다.

## 1. 갖춰진 것

| 수단 | 누가 | 어디 |
|---|---|---|
| 욕설 가림, 광고·연락처 차단, 도배 자동 입막음(30초~10분) | 서버(자동) | `server/chat.js` |
| 신고(채팅 한 줄마다 버튼) | 이용자 | `/api/report` → reports 표 |
| 차단(그 사람의 채팅을 내 기기에서 숨김) | 이용자 | 기기 |
| **신고 열람, 채팅 금지, 계정 정지, 제재 이력** | 운영자 | `server/admin.js` (이 문서) |

관리용 웹 화면과 원격 API는 없다. 서버에 SSH로 들어온 사람만 제재할 수 있다(공격받을 곳을 늘리지 않으려는 것).

## 2. 명령

서버(VM `rtd-online`)에 들어가서 돌린다. 환경 변수는 서버와 같은 것을 쓴다(그래야 같은 DB를 본다).

```bash
gcloud compute ssh rtd-online --zone asia-northeast1-b --project mikoserver-513016 --account mikohatsu97@gmail.com

# 매번 길게 치지 않도록(그 접속 동안만)
adm() { sudo -u rtd env $(sudo cat /etc/rtd-online.env | xargs) node /opt/rtd-online/server/admin.js "$@"; }

adm reports                       # 최근 7일 신고 목록 + 대상별 요약
adm reports --days 1              # 어제부터
adm reports --days 30 --target g1a2b3c4d5e6f
adm user g1a2b3c4d5e6f            # 계정 요약(닉네임·제공자·가입일·판 수·받은 신고·현재 제재)
adm user 닉네임                   # 닉네임으로 찾기(같은 닉네임이 여럿이면 모두 보인다)
adm mute g1a2b3c4d5e6f 1d "욕설"
adm mute g1a2b3c4d5e6f 7d "욕설 반복"
adm unmute g1a2b3c4d5e6f
adm ban g1a2b3c4d5e6f 30d "부정행위(결과 조작)"
adm ban g1a2b3c4d5e6f perm "혐오 발언 반복"
adm unban g1a2b3c4d5e6f
adm log                           # 제재 이력(누가 언제 무엇을)
```

- 기간: `1h` `1d` `7d` `30d` `perm`(숫자+h, 숫자+d도 된다. perm = 영구, 저장은 9999-12-31).
- 제재는 **계정 ID**로만 건다(닉네임은 겹칠 수 있다). 사유는 꼭 적는다(200자까지, 이력에 남는다).
- 명령 첫 줄의 `[저장소] PostgreSQL(DATABASE_URL)`을 확인한다. `JSON 파일 …`이 나오면 환경 변수가 빠진 것이다(운영 DB가 아닌 곳을 보고 있다).
- 화면의 시각은 일본·한국 시간(UTC+9)이다.

### 언제 적용되나

`admin.js`는 저장소에 적기만 한다. 돌고 있는 서버가 **30초마다** 걸려 있는 제재 목록을 다시 읽는다. 그래서 걸거나 푼 뒤 최대 30초 안에:

- **채팅 금지**: 그 계정이 로비·방 채팅을 보내면 본인에게만 "채팅이 제한되었습니다(남은 시간)"가 뜨고 남에게는 전달되지 않는다. 게임은 그대로 된다.
- **계정 정지**: 열려 있던 방·로비 연결이 끊기고, 로그인(게스트·Apple·Google·아이디)과 토큰을 쓰는 모든 API, WebSocket 접속이 `403 { error: "banned", until }`으로 거절된다. 앱을 켜면 로딩 화면에서 "계정이 정지되었습니다(언제까지)"만 보이고 로비로 들어가지 못한다.
- 서버를 다시 켤 필요는 없다. 서버가 목록을 읽지 못하면(DB 장애) 앞서 읽은 목록을 그대로 쓴다.
- 정지해도 로그인 토큰은 지우지 않는다. 풀면 그 기기에서 그대로 다시 들어온다.

## 3. 신고가 오면

1. `adm reports --days 1`로 새 신고를 본다. 아래쪽 **대상별 요약**에서 "신고자 수"가 많은 계정부터 본다.
2. `adm user <계정ID>`로 그 계정의 받은 신고 수, 이전 제재를 본다. `adm log`에서 같은 계정의 지난 제재를 확인한다(반복인지).
3. 아래 기준표로 제재하고 사유를 적는다.
4. 한 사람이 24시간 안에 **서로 다른 5명 이상**에게 신고당하면 서버 기록에 한 줄이 남는다. 급한 것은 이것으로 먼저 안다:
   ```bash
   sudo journalctl -u rtd-online --since "1 day ago" | grep "\[mod\]"
   ```

### 판단할 때 알아 둘 것

- **신고의 "내용" 칸은 신고한 사람의 기기가 보낸 글이다.** 서버는 채팅을 저장하지 않으므로 그 말을 실제로 했는지 서버에서 확인할 수 없다(꾸며 낼 수 있다). 그래서
  - 신고 한 건, 신고자 한 명만으로는 제재하지 않는다(욕설이 명백하고 같은 사람에 대한 신고가 쌓여 있을 때는 예외).
  - 서로 다른 여러 사람이 비슷한 내용으로 신고했는지를 본다(요약의 "신고자 수").
  - 한 사람이 여러 계정을 반복해 신고하면 허위 신고를 의심한다(허위 신고도 제재 대상).
- **자동 제재는 없다.** 여럿이 짜고 한 사람을 신고해 내쫓는 일을 막기 위해서다. 제재는 운영자가 직접 건다.
- "대상 계정"이 `(못 찾음)`이면 신고할 때 상대가 이미 나간 것이다. 닉네임으로 `adm user <닉네임>`을 찾아본다(닉네임은 겹칠 수 있으니 확실할 때만).

## 4. 제재 기준표

| 위반 | 처음 | 반복(이력 있음) | 계속 반복 |
|---|---|---|---|
| 욕설·비하(걸러내기를 피해 쓴 것 포함) | 채팅 금지 1일 | 채팅 금지 7일 | 채팅 금지 30일 |
| 도배·방해(자동 입막음을 피해 계속) | 채팅 금지 1일 | 채팅 금지 7일 | 채팅 금지 30일 |
| 혐오 발언(인종·국적·성별·장애 등), 성적인 말, 위협·괴롭힘 | 채팅 금지 30일 | 채팅 금지 영구 | 계정 정지 영구 |
| 광고·현금 거래·외부 유도·사기 | 채팅 금지 30일 | 채팅 금지 영구 | 계정 정지 30일~영구 |
| 미성년자를 성적으로 다루는 내용, 구체적인 범죄 예고·개인정보 유포 | 계정 정지 영구(즉시) | — | — |
| 부적절한 닉네임 | 닉네임이 걸러지지 않은 경우 계정 정지 7일 + 금지어 추가(`server/chat.js`) | 계정 정지 30일 | 계정 정지 영구 |
| 부정행위(결과 조작·비정상 기록, 서버 공격) | 계정 정지 30일 | 계정 정지 영구 | — |
| 허위 신고 반복 | 채팅 금지 7일 | 채팅 금지 30일 | 계정 정지 30일 |

- 경고 단계는 따로 두지 않는다(경고를 보낼 수단이 없다). 가장 가벼운 제재가 채팅 금지 1일이다.
- 말로 한 위반은 **채팅 금지**가 기본이다. 게임 자체를 막는 **계정 정지**는 부정행위, 중대한 위반, 채팅 금지로 해결되지 않는 경우에 쓴다.
- 기준표보다 무겁게 할 때는 사유에 까닭을 적는다.

## 5. 처리 주기

- **하루 한 번** `adm reports --days 1`과 `[mod]` 기록을 확인한다. 신고는 접수 후 **24시간 안에** 확인해 조치한다.
- 스토어 심사 답변에 쓸 문장: "신고된 내용은 운영자가 24시간 이내에 확인하며, 약관 위반이 확인되면 해당 이용자의 채팅을 제한하거나 계정을 정지합니다. 욕설은 자동으로 가려지고 광고·도배는 자동으로 차단되며, 이용자는 다른 이용자를 차단할 수 있습니다."
- 일주일에 한 번 `adm log`로 기간이 끝난 제재와 반복 위반자를 훑어본다.

## 6. 이의 제기

- 연락처: **mikohatsu97@gmail.com** (개인정보 처리방침·약관의 문의처와 같다. 앱의 정지 안내에도 이 주소가 나온다.)
- 메일에 닉네임(알면 계정 ID)을 적어 달라고 한다. `adm user`와 `adm log`로 제재 사유를 확인하고, 잘못된 제재면 `unmute`/`unban` 한다(풀어 준 것도 이력에 남는다).
- 답은 7일 안에 한다.
- **정지된 계정의 삭제 요청**: 정지 중에는 앱에서 탈퇴(계정 삭제)를 할 수 없다(모든 API가 막힌다). 메일로 삭제 요청이 오면 본인 확인 뒤 `unban` 해서 직접 삭제하게 하거나, DB에서 `DELETE FROM accounts WHERE id = '…'`로 지운다. 개인정보 삭제 요청은 제재와 상관없이 들어줘야 한다.

## 7. 저장되는 것 (개인정보)

- 계정: `muted_until`, `mute_reason`, `banned_until`, `ban_reason` — 계정을 지우면 같이 사라진다.
- 제재 이력 `mod_log`: 시각, 운영자(서버 로그인 이름), 한 일, 계정 ID, 기간, 사유. 계정을 지워도 남는다(계정 ID는 무작위 글자이고 닉네임·이메일은 없다).
- 신고 `reports`: 신고자·대상 계정 ID, 신고 때의 닉네임, 신고된 글(120자), 방. 계정을 지우면 그 계정 ID 칸은 비워진다.
- 이메일·이름·기기 정보는 애초에 저장하지 않는다. `admin.js`도 위의 것만 보여 준다.

## 8. 한계 (알고 쓴다)

- 게스트 계정은 새로 만들 수 있으므로 정지를 완전히 강제할 수는 없다(새 계정은 등급·해금이 처음부터다). 같은 사람이 계속 돌아오면 그때마다 정지한다. 기기·주소 단위 차단은 넣지 않았다.
- 정지된 계정도 이미 올라간 랭킹에는 그대로 보인다(부정 기록을 랭킹에서 빼는 기능은 따로 없다).
- 서버는 채팅 내용을 기록하지 않는다. 증거는 신고에 담긴 글뿐이다(3절 참고).
- 적용까지 최대 30초가 걸린다.
- JSON 저장소(DB 없이 돌릴 때)에서는 제재가 `DATA_DIR/moderation.json`에 따로 저장된다(운영은 PostgreSQL).

## 9. DB 적용 (처음 한 번)

`server/db/migrate-2026-11-18-moderation.sql`을 운영 DB에 적용한다(여러 번 돌려도 안전). 같은 내용이 `schema.sql` 끝에도 있어 서버와 `admin.js`가 시작할 때 다시 적용한다 — `ALTER TABLE`은 표의 소유자만 할 수 있으므로, 서버의 DB 사용자가 `accounts` 표의 소유자인지 먼저 확인한다(아니면 서버가 시작하다 멈춘다).

```bash
sudo -u rtd env $(sudo cat /etc/rtd-online.env | xargs) sh -c 'psql "$DATABASE_URL" -f /opt/rtd-online/server/db/migrate-2026-11-18-moderation.sql'
```
