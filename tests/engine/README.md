# 게임 규칙 자동 시험 (tests/engine)

유형: Logic / Integration · 게이트: BLOCKING(알려진 버그 줄은 아래 표 참고)

`engine.js`·`raid.js`·`theme-samguk.js`·`ai.js`·`net.js`를 Node에서 그대로 불러와,
AI 사령관(`ai.js`의 `Brain`)과 가상 방(`RTD_NET.hub()`)으로 사람 입력 없이 판을 끝까지 돌린다.
외부 의존성은 없다(Node 22만). 출력은 `server/test/store-smoke.js`와 같은 줄 단위 `OK` / `FAIL`.

## 돌리는 법

```
node tests/engine/run.js            # 전부. 실패가 하나라도 있으면 종료 코드 1
node tests/engine/run.js t4 t5      # 이름 앞부분으로 골라 돌리기
node tests/engine/t1-smoke.js       # 하나만 직접
```

줄의 뜻:
- `OK` 확인했고 맞다.
- `FAIL` 확인했고 틀리다. 종료 코드 1.
- `SKIP` **이 시험이 확인하지 못한 것**. 통과가 아니다. 무엇을 못 봤는지 적혀 있다.
- 맨 끝 `RESULT 이름 ok= fail= skip= ms=` 줄을 `run.js`가 읽는다. 이 줄 없이 끝나거나, `OK`가 0개인 시험은 실패로 센다.

난수: 게임은 `opt.seed`로 씨앗을 고정한다. `lib.js`는 이 프로세스 안의 `Math.random`도 씨앗 있는 것으로 바꾼다(`net.js`·`Game.restore`가 씀). 그래서 같은 코드면 같은 결과가 나온다(T1이 두 번 돌려 확인한다). 게임 코드가 바뀌면 같은 씨앗이라도 판의 흐름이 달라진다.

300걸음(게임 시간 10초)마다 보는 불변식(`lib.js`의 `makeWatch`):
- 유닛·적·아이템·보스전·플레이어·통계의 모든 숫자가 유한(NaN·Infinity 아님)
- `lives >= 0`, `gold >= 0`, 적 수 ≤ 한도 + 10, 유닛 좌표가 `INNER` 안, 출전 장수 좌표가 `ARENA` 안, 장수 체력 ≤ 최대
- `round`가 줄지 않음, `phase`가 `wave|bossIntro|bossPick|boss|over` 중 하나, `wave`이면 `fight === null`, 보스 단계이면 `fight`가 있음
- 보스 체력이 `0..mhp` 안
- 멈춤 감시: 게임 시간 120초 동안 `round`·`phase`·`fight.t`가 모두 그대로면 실패

줄 앞에 `[B-xx]`가 붙은 것은 그 버그를 재현하는 줄이다. 고치기 전에는 실패가 정상이고, 고친 뒤에는 회귀 시험이 된다.

## 이 시험이 못 잡는 것

- **화면**: `ui.js`(`src/ui/*`)는 불러오지 않는다. 그리기, 버튼, 터치, 노치, 4개 언어 문구 길이.
- **사람 조작**: 조이스틱(`g.manual`, `c.joy`, `c.atkHold`, `g.laneJoy`)과 스킬 버튼. AI는 이 경로를 쓰지 않는다. 보스전이 아닐 때 버튼을 누르는 경우(B-10)도 없다.
- **실제 통신**: 가상 방은 메시지가 늦거나 빠지거나 순서가 바뀌지 않는다. WebSocket 끊김·재접속, 서버의 자리 비움 처리(5~10초), 60초 안 복귀(B-02, B-05, B-06, B-08, B-09). t5의 방장 빼기는 즉시 빠지는 흉내다.
- **앱 내리기·올리기**, 저장 위치(localStorage)와 깨진 저장 파일 처리(화면 코드 몫).
- **광고·로그인·결제**(`native.js`, 서버).
- **성능**: 프레임, 메모리, 발열. 여기서 재는 시간은 계산 시간일 뿐이다.
- **후반 콘텐츠**: AI는 쉬움만 이긴다. 보통·어려움·악몽 후반 보스(예: 110라운드 등애)는 거의 밟지 못한다. 각 시험이 진 라운드와 못 본 보스를 `SKIP`으로 적는다.
- **수치 밸런스**: 규칙 효과의 값이 설계와 맞는지는 보지 않는다. 판이 돌고 불변식이 지켜지는지만 본다.

이 범위는 qa.md 4절의 실기기 수동 시험으로 확인한다.
